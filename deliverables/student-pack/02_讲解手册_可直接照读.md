# Cloudrest Wines 项目讲解手册

下面内容可以直接用于给 Mia、Zora、Rianna、Jason 说明后续怎么完成项目。

## 开场

我们现在做的是 BISM2207 的 Cloudrest Wines 数据库项目，方向已经确定为 Human Resources, Workforce Planning and Wellbeing。

目前数据库结构、HR 扩展、五个业务规则、五个 integrity tests、六个 decision-support queries、data dictionary 框架、ER model 框架、报告主体内容和视频流程都已经准备好了。

现在大家主要需要完成真实的 MySQL Workbench 操作、截图、最终 ER model、个人信息补全、后续 Official A2 Workbook、Week 11 Assigned Scenario、RiPPlE 和视频。

大家不需要操作 Git。需要使用的文件会直接发给你们。

## 第一部分：先建立数据库

大家收到文件以后，先找到 `Cloudrest_Wines_Database.sql`。

打开 MySQL Workbench，打开自己的本地 connection，然后点 File，点 Open SQL Script，选择这个 SQL 文件。

打开以后点击闪电按钮执行整个脚本。

执行结束以后，在左边 SCHEMAS 位置点刷新，应该可以看到一个叫 `cloudrestwines` 的 schema。

只要整库能够正常执行，后面截图和视频就都基于这个数据库进行。

如果这里出现红色报错，先不要继续截图，把完整错误信息保存下来确认。

## 第二部分：Zora 处理 ER Model

Zora 负责最终 ER Model。

打开 `Cloudrest_Wines_Model.mwb`，进入完整 EER Diagram。

然后点 Model，点 Relationship Notation，选择 UML。

这个步骤必须确认，因为最终要求使用 UML notation。

然后把完整 diagram 整理成横向宽布局，所有表尽量不要重叠，entity name、attributes、PK、FK 和 cardinalities 都要能看清。

整理完成以后保存 `.mwb`，然后重新导出完整 ER Diagram PNG。

导出以后自己打开图片检查一下。如果放大以后字段仍然看不清，就继续调整布局再导出。

最终把 `.mwb` 和 PNG 发给 Mia。

## 第三部分：Jason 负责规则和 integrity test 截图

这部分总共需要六张不同的截图，其中一张是 valid test，五张是 rule rejection。

第一张运行 `t01_validtraining.sql`。

这张图需要证明一条完整的 training record 可以正常被数据库接受，测试结束以后会 rollback。

第二张运行 `t02_invalidroledate.sql`。

这张图需要证明 employee role 的结束时间不能早于开始时间，应该看到 Error 3819 和 `chk_employeerole_dates`。

第三张运行 `t03_missingreordercomment.sql`。

这张图需要证明 `reorderFlag = FALSE` 的时候必须填写 explanation，应该看到 Error 3819 和 `chk_bottletype_reorder`。

第四张运行 `additional_postalshipment.sql`。

这张图需要证明 PO Box、Private Bag 或其他非 physical address 不能作为 shipment address，应该看到 Error 1644。

第五张运行 `t04_unpaidshipment.sql`。

这张图需要看到数据库拒绝未付款订单发货，错误信息里面应该有 `Order must be paid before shipment`。

第六张运行 `t05_overlappingsupervision.sql`。

这张图需要证明同一个 employee 在同一段时间不能同时有第二个 supervisor，应该看到 Error 1644。

截图的时候尽量把 SQL editor 和下方的 Result Grid 或 Action Output 一起截进去。不要只截错误的一小块，也不要把关键 SQL 裁掉。

这六张图里面，部分图片同时用于 Task 3 和 Task 6，所以相同测试不需要重复做。

## 第四部分：Rianna 负责 Query 截图

打开 `Cloudrest_Wines_Queries.sql`。

六个 query 要分别运行。

Query 1 是 training coverage。

运行以后截一张结果图，能看到不同 operational area 的 training coverage。

Query 2 是 incident rate per 1,000 labour hours。

运行以后截一张结果图，能看到 labour hours、incident count 和 rate。

Query 3 是 latest safety training 前后的 incident comparison。

运行以后截一张结果图。

Query 4 是 overtime 和 supervisor review 相关分析。

运行以后截一张结果图，同时确认结果里没有显示 confidential wellbeing note。

Query 5 是 stored procedure。

先运行：

`CALL getExpiringQualifications(30);`

截一张图。

然后运行：

`CALL getExpiringQualifications(90);`

再截一张图。

这两张都需要保留，因为视频也要求展示两个不同参数。

Query 6 是 open corrective actions。

先运行 Query 6，截一张结果图。

然后运行它对应的 EXPLAIN，再截一张 execution plan。

这样 Query 部分总共八张图。

加上 Jason 前面的六张，一共是十四张不同截图。

## 第八部分：RiPPlE

RiPPlE 需要使用真实 prompt progression。

目前建议的两个主题已经确定。

第一个主题是 employee role history 和 supervisor history 的 conceptual modelling。

第二个主题是 shipment 不能使用 PO Box 或 Private Bag 的 constraint development。

每个主题都保留 initial prompt、AI output、evaluation、至少两次 revised prompt、每次改进后的 output 和最终 validation。

不要等到最后才临时补过程。每次实际修改 prompt 的时候就保存下来。

Peer Review 的数量和字数要求等 Tutor 最终确认以后再执行。
