## 二、MySQL Workbench 建库

建议由 Jason 主操作，其他成员至少要能打开数据库并运行自己负责的视频部分。

1. 打开 MySQL Workbench。
2. 打开自己的本地 MySQL connection。
3. 点击 `File`。
4. 点击 `Open SQL Script`。
5. 打开 `Cloudrest_Wines_Database.sql`。
6. 点击闪电按钮执行整个脚本。
7. 等待执行结束。
8. 左侧找到 `SCHEMAS`。
9. 点击刷新按钮。
10. 确认出现 `cloudrestwines`。
11. 展开 `cloudrestwines`，确认能看到 Tables、Views 和 Stored Procedures 等对象。

如果整库执行出现红色错误，请先停止后面的截图和视频，把完整错误信息发给项目负责人确认。

提醒：数据库脚本会重新建立 `cloudrestwines`。不要在同名数据库中保存无法恢复的个人数据。

## 三、Zora 完成最终 ER Model

1. 用 MySQL Workbench 打开 `Cloudrest_Wines_Model.mwb`。
2. 打开完整 EER Diagram。
3. 点击 `Model`。
4. 点击 `Relationship Notation`。
5. 选择 `UML`。

10. 确保 entity name、attributes、PK、FK 和 cardinalities 都能看清。
11. 保存 `.mwb` 文件。
12. 重新导出完整 ER Diagram PNG。
13. 打开导出的 PNG 自己检查一次。
14. 把最终 `.mwb` 和 PNG 发给 Mia，用于最终报告。

2. 记录 sheet 名称和原始 row count。
3. 导入 staging table。
4. 检查 missing required values。
5. 检查 duplicate identifiers。
6. 检查 data type 和 date format。
7. 检查 invalid domain values。
8. 检查 negative numeric values。
9. 检查 percentage 范围。
10. 检查 referential-integrity 问题。
11. 可以确定的 correction 用 SQL 记录。
12. 无法确定的记录放入 exception list，等待人工确认。
13. 保存 correction 前的结果截图。
14. 执行 correction SQL。
15. 保存 correction 后的结果截图。
16. 导入正式 `cloudrestwines`。
17. 核对 `source rows = accepted rows + rejected rows`。
18. 把真实 error、correction SQL、before / after evidence 放入 Task 6a。
